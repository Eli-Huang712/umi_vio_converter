# ============ CONCLUSION ============
# The per-process critical path = build_map's SINGLE-THREADED ROS2 message plumbing:
#   ROS CDR image serialization (sensor_msgs/_image.py generator-expression byte copy) + rclpy executor spin
#   + paced flatbuffer bag-replay decode. This is pure-Python, GIL-bound, ~1 core/process.
# This mechanism explains ALL observations:
#   - CPU never saturates (each build_map ~1 core, not many) -> node caps ~PAR 64 well below 192 cores
#   - GPU 7% active (build_map barely uses GPU; it shuffles messages) -> not GPU-bound
#   - MPS zero gain (no GPU-context contention to relieve) -> refutes the prior serialization hypothesis
#   - per-proc latency inflates with co-tenancy (shared paced-replay + DDS + CPU contention on the serial path)
